## 0. 五分钟上手

```bash
pip install -r requirements-dev.txt

python -m imgdedup_ui                     # 起界面
python -m unittest discover -s tests -p "test_*.py"   # 全量测试
python dev/check_no_network.py            # 门禁：测试不许联网
python dev/check_fresh_clone.py           # 门禁：按 git 的口径在干净副本里再跑一遍
python -m dev.make_installer --build      # 出免安装版 + 安装包
```

「深度」档需要外置 CLIP 模型，取一次即可（85 MB）：

```bash
python -m dev.fetch_model
```

缺 cv2 会让扫描不可用。开发机上直接 `pip install opencv-python` 最省事，
但打包产物**不带**它 —— 它是外置组件。

改动之前先看第 9 节（编码约定）和第 10 节（踩坑清单）。这两节里的每一条
都是实际付出过代价换来的，不是风格偏好。

## 1. 目录结构与分层

```
imgdedup_core/   核心引擎。无 Qt 依赖，可独立测试、可替换
  扫描 → 解码 → 特征 → 分组 →（可选）语义 → 持久化
imgdedup_ui/     PySide6 界面。三栏布局 + 网格虚拟化 + 后台扫描线程
dev/             打包、取外置组件、截图、探针、门禁脚本。不进发布产物
tests/           单元测试
resources/       图标（icon.ico / icon.png）
                  models/ 是外置模型的**开发来源**，不进 git
docs/            本目录
```

两条分层约束，不是风格偏好：

1. **`imgdedup_core` 里不许出现 GUI 依赖**（PySide6 / PyQt / tkinter）。
   它是"引擎可被独立测试与替换"的保证。由
   `tests/test_guardrails.py::TestCoreDecoupling` 在**子进程**里断言
   （子进程是为了避开全量套件里 Qt 已经加载导致的误报）。
2. **界面层对核心引擎的引用一律写在方法内部或后台线程里。**
   `imgdedup_core.feature` 会拉起 cv2 + numpy，导入是秒级的；
   放在启动路径上会直接毁掉「首屏 < 1 s」这个目标。
   `imgdedup_ui/__init__.py` 和 `worker.py` 的模块顶层都不 import core。

## 2. 核心引擎 `imgdedup_core`

`__version__ = "1.0.0"`，**版本号只有这一个来源**：`dev/make_installer.py`
用正则从 `imgdedup_core/__init__.py` 读它，再以 `/DAppVersion=` 传给 ISCC。
别在别处再写一份（`imgdedup_ui` 里没有 `__version__`，原因见第 9 节）。

### 2.1 模块总览与依赖方向

| 模块 | 一句话职责 | 依赖 | 碰 cv2 |
|---|---|---|---|
| `infra.py` | 格式化、内存闸门、分阶段计时、节流进度、CPU 线程预算 | 纯标准库（psutil 惰性） | 否 |
| `scan.py` | 目录遍历、排除规则、文件身份 `(dev, ino)`、硬链接识别、大小分桶 | 无 | 否 |
| `opencv.py` | 外置 cv2 的定位、`sys.path` 注入、惰性代理、缺组件提示 | 无 | **是**（唯一真正 `import cv2` 的地方） |
| `cv2_fetch.py` | 从 PyPI 找/下/解 opencv wheel 到 `extra/cv2/` | 无 | 否 |
| `decode.py` | 格式嗅探 + 多级瀑布路由（vips / Pillow / pdfium）、元数据、缩略图、动图 | numpy / Pillow / pyvips / pypdfium2 | 否 |
| `feature.py` | 两级精确哈希、pHash / dHash、HSV 直方图、汉明距离 | `opencv`（惰性代理） | 惰性 |
| `group.py` | 并查集聚类 + 推荐保留项 | `feature` | 间接 |
| `embed.py` | CLIP ONNX 嵌入 + 余弦聚类 + 过合并隔离 | `group`、`opencv` | 惰性 |
| `cache.py` | 两级缓存：指纹复用库（SQLite）+ 缩略图磁盘缓存（WebP） | `opencv`、`decode`（方法内惰性） | 惰性 |
| `catalog.py` | SQLite/WAL 持久化：扫描、文件、分组、设置 | 无 | 否 |
| `action.py` | **路径 A**：用户删除（回收站/指定目录 + 撤销记录） | `feature`、`group`（函数内延迟导入） | 间接 |
| `scratch.py` | **路径 B**：开发/测试垃圾真删（白名单护栏） | 无（不引用 `action`） | 否 |

依赖链：`embed → group → feature → opencv`；`cache → decode` / `cache → opencv`。

`__init__.py` 的 `__all__` 只列了 7 个模块（外加 `__version__`），
但 `action` / `cache` / `cv2_fetch` / `embed` / `opencv` 都是正常可导入的 ——
`__all__` 只影响 `from imgdedup_core import *`，别把它当成"这些模块不存在"。

### 2.2 逐模块要点

#### `infra.py`

- `MemGate(budget_bytes)`：按**预计解码字节数**限流的并发闸门，
  `reserve(need)` 是上下文管理器，`need` 夹在 `[1, budget]`。
  按字节而不是按文件数限流是关键：同样 12 并发，1 万张 200 KB 的图和
  1 万张 30 MB 的图差上百倍内存。
- `default_memory_budget(cap_bytes=2 GiB)` = `min(物理内存 × 0.5, 2 GiB)`；
  拿不到 psutil 时按 8 GiB 估。
- `cpu_budget(ratio=0.75)` = `max(1, min(n, n × 0.75))`。
- `Timings` / `Progress(label, total, every=500)`：阶段计时与节流上报。
- `human_bytes` / `human_secs` / `human_rate`。
- 注意：`infra.estimate_decode_bytes(w, h, bands, bytes_per_band)` 和
  `decode.estimate_decode_bytes(meta, target)` 是**两个不同的函数**，
  语义也不同，引用时别混。

#### `scan.py`

- `FileEntry` 是贯穿全流程的数据载体，字段按阶段分组
  （基础 / 填充 / 特征 / 语义 / 缓存命中标记）。
  `identity` 属性就是 `(dev, ino)`；`pixels` 是 `width * height`。
- `walk(root, exclude_dirs=..., min_size=1, follow_links=False)`：
  只产出 `isfile()` 且 `size >= min_size` 的项，**0 字节文件被跳过**。
- 排除规则：目录名 8 项（`.scratch` / `.imgdedup` / `.git` / `.svn` /
  `__pycache__` / `node_modules` / `$RECYCLE.BIN` / `System Volume Information`），
  外加前缀 `~$`、`._`（Office 临时文件、macOS 元数据）。
- `find_hardlink_groups(entries)`：只返回 `len > 1` 的组，`ino == 0` 跳过。
- **硬链接必须在去重前识别。** 硬链接的多个路径共享同一个 inode，
  删掉其中一个不释放任何空间；不识别就会让用户"删了一堆、磁盘一点没变"。

#### `opencv.py`

外置 cv2 的加载器，也是全仓库唯一真正执行 `import cv2` 的地方。

- 候选目录顺序：`<exe 同级>/extra` → `<exe 同级>/_internal/extra`（onedir）
  → `sys._MEIPASS/extra`（onefile）→ 源码树 `extra/`。
- `install_path_hook()` 把候选目录**插到 `sys.path` 最前**，
  保证用户的 `extra/` 优先于 site-packages 里的旧版。
- `lazy_cv2` 是 `__getattr__` 代理：业务模块写
  `from .opencv import lazy_cv2 as cv2`，第一次真正用到属性时才导入。
  这样"缺组件"不会变成"窗口都建不出来"的闪退。
- `require()` 失败时抛带人话说明的 `ImportError`，不静默降级 ——
  静默降级会让人以为是自己算法有问题。
- `refresh()` 会清缓存：用户刚把 cv2 放进去却继续报缺组件，就是缓存没清。

#### `cv2_fetch.py`

- 从 `https://pypi.org/pypi/opencv-python/json` 找 wheel，**从新到旧最多试 40 个版本**。
  不能只看最新版：某些版本可能没出对应平台的轮子。
- **不能按 `cp313` 过滤**：opencv 用的是稳定 ABI，文件名是
  `cp37-abi3-win_amd64`，按 `cp313` 过滤会得到"零个可用版本"。
- 解包时跳过 `data/`（haarcascade XML，6+ MiB）、`__pycache__/`、
  `*opencv_videoio_ffmpeg*`（两个 DLL 共 51 MiB）。这套 `should_skip`
  与 `imgdedup.spec` 的二进制裁剪共用同一份规则。
- 解压后校验 `cv2/cv2.pyd` 存在，否则报"不是 Windows 版"。

#### `decode.py`

三级瀑布路由：**libvips → Pillow → pypdfium2**。三级是必要的，
不是过度设计：libvips 没打包 ImageMagick 委托，合法的 BMP / PDF 会直接报
`is not a known file format`。

- 扩展名分组：`VIPS_EXTS`（jpg/png/gif/webp/tif/svg/heif/avif/jp2/jxl…）、
  `PILLOW_EXTS`（bmp/psd/ico/tga/pcx…）、`PDF_EXTS`（`.pdf` / `.ai`）、
  `HEADER_EXTS`（`.eps` / `.svgz`，只读文件头）。
- `sniff_format()` 走魔数嗅探（含 RIFF-WEBP、`ftyp` 品牌、`<?xml` / `<svg`）。
- **一律走 shrink-on-load / 小尺寸缩略图，永不整图解压。**
  实测：47 MP 全解码 134 MB / 346 ms，256 px 缩略图 2.2 ms。
- `_Backends.probe()` 的线程安全是个坑：早先 `_probed` 置位早于导入，
  9 个线程里 8 个看到 `_pil = None`，"3201 个文件只解析出 1 个"。
  修法是双重检查 + 锁，**只在全部导入完成后才置位**，并把被吞的异常记进 `errors`。
- 缩略图瀑布的路由是**实测选出来的**，不是猜的：默认 Pillow 优先
  （240 个样本中位 14.9 ms，pyvips 23.3 ms，后者每次调用约 11 ms 固定开销），
  超大 PNG/TIFF 反转为 vips 优先。
- 动图（`Animation` / `load_animation` / `is_animated`）只用 Pillow：
  libvips 的 `page-height` / `delay` 语义不稳，WebP 上常缺 duration。
  三道上限：`ANIM_FRAME_SIZE=512`、`ANIM_MAX_FRAMES=300`、
  `ANIM_MAX_BYTES=300 MB`；帧时长夹在 `ANIM_MIN_MS=20` ~ `ANIM_MAX_MS=10000`。
  超限**截断播放**而不是拒绝加载。
- `.gif` 不一定是动图（单帧 GIF 很常见），所以 `is_animated()` 优先看
  `meta.animated` / `meta.frames > 1`，扩展名只当"值得一试"。
- 多页 PDF 走**按帧处理**：`_meta_pdfium` 把 `frames = 页数`、
  `animated = 页数 > 1`，于是 `is_animated()` 对多页 PDF 返回 `True`。
  这是有意的 —— `tests/test_pdfium_backend.py::test_multi_page_reports_frames`
  里写着理由（"多页 PDF 要标成 animated（按帧处理）"），不是把"多页"误当成"动图"。

#### `feature.py`

- 精确哈希用 **XXH3-128**（`xxhash`）：128 位非加密哈希，1 万张图的碰撞概率
  约 10⁸ / 2¹²⁸ 量级，可忽略；且删除前还有逐字节确认兜底。
- 两级策略：先算 `quick_hash`（头 `QUICK_HEAD=64 KiB` + 尾 `QUICK_TAIL=64 KiB`
  + 文件大小小端 8 字节一起入哈希）筛掉唯一文件，只对短指纹碰撞的候选算
  `full_hash`。**短指纹只用于筛候选，最终判定必须是全量哈希。**
- `byte_identical(a, b)` 是删除前的第三道闸。
- 感知特征：`phash()`（DCT 低频 8×8，中位数阈值）、`dhash()`（9×8 水平梯度）、
  `hist_hsv(rgb, bins=16)`（HSV 三维各 16 bin，拼接后归一化）。
  `hist_distance()` 返回 `1 - min(a,b).sum()`：0 = 完全一致，1 = 完全不重叠。
- `pairwise_hamming_block()` 用 `np.bitwise_count` 向量化算汉明距离。

#### `group.py`

- `UnionFind(n)`：路径减半 + 按秩合并，`union(a, b, score)` 记录边权。
- `exact_groups(entries, hardlink_protected=...)`：按 `(size, full_hash)` 分桶，
  跳过被保护的项与没有 `full` 的项。
- `perceptual_groups(entries, params=PerceptualParams(), *, exclude=None)`，
  默认参数：`phash_max=6`、`dhash_max=12`、`hist_max=0.35`、`block=256`。
  `exclude` 里的下标不参与聚类，调用方用它把已经在更强的分组里出现过的文件
  排除掉（理由见下面"每个文件只进一类"）。
- 默认阈值实测的**容忍边界**（三张不同题材的 3600×2400 JPEG，中心裁剪后重存
  JPEG；括号里是 pHash / dHash / 直方图三项距离，加粗的是超线那项）：
  保留 99% 时三张都还归得到一组（2/3/0.01、2/0/0.01、2/1/0.02）；
  保留 95% 时两张抓不到（山脊 **8**/2/0.03、城市 6/**15**/0.04）；
  保留 90% 时三张全抓不到。
  三项判据里 **pHash 最先超线**，直方图最宽松 —— 裁到 50% 也才 0.36（阈值 0.35）。
  所以"裁过边"只在裁剪极小时落在默认阈值内。想放宽就调 `phash_max`，
  但余量不大：两张**无关**的图实测 pHash 距离是 14（`山脊_01` vs `城市_03`）。
  判定式 `(phash 距离 <= 6) & (dhash 距离 <= 12)`，再加直方图距离约束；
  相似度记作 `1 - (pd + dd) / 128`。
  分块是为了避免 N² 全矩阵（1 万张 = 1 亿元素）。
- `recommend_keeper(entries, group, prefer_lossless=True)`：
  评分 `(pixels, size, lossless_rank, mtime_ns)` 取最大，`lossless` 集合是
  `{PNG, TIFF, BMP, PSD, WEBP}`。
- `keeper_reason()` 生成给用户看的理由，它判"无损"用的集合是
  `{PNG, TIFF, BMP, PSD}`（**不含 WEBP**）。同一个事实在同一个模块里有两个落点，
  违反了 9.2 节那条单一来源规则。
  影响面实测过：`lossless_rank` 排在 `size` 之后，所以它只在像素数与字节数
  **都完全相等**时才决定胜负；而那种情况下 `keeper_reason` 的"分辨率最高""文件最大"
  两条（用的是 `== max`）必然已经成立，理由不会为空也不会说错，只是少一个"无损格式"。
  也就是说这是**代码卫生问题，不是用户能察觉的 bug**。
  真要统一的话得先定 WEBP 算不算无损（它两种模式都有）——
  把 WEBP 从 `recommend_keeper` 的集合里去掉，会让那种平局改由 `mtime_ns` 决定，
  推荐项可能从 WEBP 变成 JPG，那是行为变更。

#### `embed.py`

- `MODEL_REPO = "Xenova/clip-vit-base-patch32"`，默认取 int8 量化版
  （`vision_model_quantized.onnx` → 落盘名 `vision_model.onnx`，85 MB）；
  `--fp32` 是全精度版（335 MB）。
- 模型目录解析，按优先级：
  `model_extra_dir()`（`<exe 同级>/extra/models`）→ `bundled_root()` 的 5 个候选
  → `model_root()`（`~/.cache/imgdedup/models`，可用 `IMGDEDUP_MODEL_DIR` 覆盖）。
  函数名带 `bundled_` 是历史原因，模型现在是外置组件。
- **`ClipEncoder.load()` 不联网。** 后台悄悄下 85 MB 会让用户以为卡住，
  而且 CI 会"跑一遍测试顺便下模型"卡十几分钟。下载只能由 UI 显式发起
  （`ensure_model()`）或跑 `python -m dev.fetch_model`。
- `ensure_model(dest=...)` 的 `dest` 语义是**根目录**，内部还会再拼一层
  `repo_slug`。少拼一层就会"下载成功却永远读不到"。
- `DEFAULT_THRESHOLD = 0.97`，**这个值必须按图库调，不是通用常数**。
  依据（3197 张同题材图库）：两两余弦 p50 = 0.773、p99 = 0.916、
  p99.9 = 0.946，中位图最近邻 0.9867；用 0.92 会合并出 1554 张的巨型组；
  阈值扫描的拐点在 0.97。
- `DEFAULT_MAX_GROUP = 200`：超过这个规模的连通分量进 `oversized`，
  **绝不参与批量删除**。
- `cosine_groups(..., exclude=None)` 的 `exclude` 同上。注意 `vectors` 的第 k 行
  对应 `idx` 的第 k 项，所以**下标和向量必须同步过滤** —— 只滤一边会让分组
  静默指到别的文件身上（不报错，结果错）。
- 内存论证：缩略图 224×224×3 = 147 KB/张（1 万张 1.4 GB），
  嵌入 512×4 B = 2 KB/张（1 万张仅 20 MB）。所以 `concat_results()`
  支持"分块解码 → 分块编码 → 立刻释放"。

#### `cache.py`

两级缓存，都按 `(规范化绝对路径, 文件大小, mtime_ns)` 做 key：

| 级别 | 类 | 落盘 | 作用 |
|---|---|---|---|
| 指纹复用库 | `FingerprintStore` | `cache/cache.db`（SQLite） | 文件没动过就完全不算，这是"重扫进秒级"的主要来源 |
| 缩略图缓存 | `ThumbStore` | `cache/<前2位>/<hash>.webp` | 感知阶段与界面网格共用同一份 WebP 产物 |

- `entry_key()` = `normcase(normpath(abspath(path))) + "|" + size + "|" + mtime_ns`。
- 缩略图 key = `blake2b(f"{norm}|{size}|{mtime_ns}", digest_size=10)`，
  落盘路径是 `root / key[:2] / f"{key}.webp"`；写入走
  `.webp.part` + `os.replace` 原子替换。
- `ThumbStore(size=256, quality=80)`：256 px 缩略图约 10–25 KB，
  1 万张 100–250 MB。
- `should_skip_features(pixels, limit=100_000_000)`：超过 1 亿像素跳过感知哈希
  （仍参与精确哈希与尺寸比对）。是**跳过**而不是"降低目标尺寸"：
  实测 233 MP JPEG 的缩略图要 210 ms，目标从 256 降到 64 几乎不变 ——
  成本在熵解码，不在输出尺寸。
- `prune(keep_days=90)` 清理过期记录。
- 已知取舍：**改名或移动会让缓存失效**（key 里含路径）。
  要做到"改名也不失效"得换成 `(卷序列号, 文件索引)` 做 key。
- 措辞提醒：`FingerprintStore` 是带 `prune` 的**持久存储**，不是有淘汰策略的
  缓存；docstring 里"两级缓存"这个叫法是历史遗留。

#### `catalog.py`

SQLite（`journal_mode=WAL`、`synchronous=NORMAL`），7 张表：
`scans` / `files` / `groups` / `group_members` / `operations` /
`protected_rules` / `settings`，`files` 上有 5 个索引 + `UNIQUE(scan_id, path)`。

- `phash` / `dhash` 是 64 位无符号值，超出 SQLite 有符号 64 位 INTEGER 范围
  （实测直接 `OverflowError`），所以存前用 `i64()` 映射到有符号区间，
  读的时候按同规则还原。
- `insert_files(batch=1000)`：每 1000 行提交一次，避免逐行 fsync。
- **现状要说清楚**：`begin_scan` / `insert_files` / `insert_group` / `end_scan`
  这套"扫描结果落库"的接口，目前**只有 `dev/run_cli.py` 在用**。
  GUI 只用了 `get_setting` / `set_setting`（记住删除方式与目标目录）。
  也就是说 `catalog.db` 里现在存的是删除偏好，不是扫描结果。
- `files` 表**没有 `hist` 列**（`cache.py` 的 `fingerprints` 表有），
  感知直方图在 catalog 里不落库。目前没有"从 catalog 读回文件、重做感知分组"的路径，
  所以这个缺口不影响任何功能；真要支持增量重算时才需要补上。

#### `action.py` —— 路径 A（用户删除）

**这是本项目安全性的核心，改动前先读完这一节。**

删除分"计划"和"执行"两步：`plan_deletions()` / `plan_from_paths()` 产出 `Plan`
（含被拦下的 `blocked`），`execute(plan, decision, ...)` 落盘并写 manifest。

五条不变量，任一条不满足就把该项放进 `blocked` 而不是硬来：

1. 每个重复组**至少保留 1 张**，禁止整组清空；
2. 待删项必须位于本次扫描根之下（`normcase + normpath` 比较）；
3. 硬链接（同一 inode 的多个路径）不参与删除；
4. 精确重复组在删除前做**逐字节确认**，把哈希碰撞的风险归零；
5. 还原前校验哈希，目标位置已存在时报告冲突，**不覆盖**。

执行阶段的去向由用户在对话框里选：`MODE_RECYCLE`（默认，走系统回收站）
或 `MODE_MOVE`（移动到指定目录，保留原目录结构，默认目录在扫描根同级）。
首次删除必须让用户明确选一次，不做静默默认。

几个必须守住的实现细节：

- `dry_run=True` **不得创建任何东西**。实测踩过：dry_run 也把目标目录建出来了。
- `_to_recycle` 的判据是"操作后目标是否还存在"，不是"有没有抛异常" ——
  send2trash 存在"实际成功却报错"的情况（实测 `FileNotFoundError`）。
- `_to_dir` 拒绝覆盖已存在的目标；移动后原路径仍存在则判失败。
- manifest 必须先落盘再认为操作完成：`.part` → `flush` → `os.fsync` → `os.replace`。
- `plan_deletions` 里 `feature` / `group` 是**延迟导入**的：`feature` 会拉起
  cv2 + numpy（秒级），而 GUI 启动路径碰到 `action` 就会 import 本模块。

manifest 结构（JSON）：

```
version(=1), id(ULID), ts, mode, target_dir, root, kind, dry_run,
totals{files, bytes, failed, planned},
blocked[], items[{src, dst, size, group, status, note}]
```

`status` 取值 `pending` / `dry-run` / `skipped`（文件已不存在）/ `ok` / `failed`；
回收站去向的 `dst` 记作 `<回收站>`。`undo()` 会回写
`undone`（仅当 `failed == 0`）、`undone_ts`、`undo_result`。

撤销走 Windows 回收站的 `$I` / `$R` 配对：`build_bin_index()` 扫 `$I*`，
偏移 8 是文件大小、16 是删除时间、24 是名称长度、28 起是 UTF-16LE 原始路径，
配对 `$R` 存在才入索引。建索引是因为：撤销 268 个文件时逐个重扫约 5 千条 `$I`
是 268 × 5000 次读取，实测不可用。所以按卷惰性建一次、整批复用。

#### `scratch.py` —— 路径 B（开发垃圾真删）

和路径 A 语义完全相反，因此**不共享任何函数**：

| 路径 | 模块 | 语义 | 用在哪 |
|---|---|---|---|
| A | `action.py` | 永不真删，走回收站或指定目录，写撤销记录 | 用户删重复图 |
| B | `scratch.py` | 真删（不进回收站） | 开发 / 测试垃圾 |

隔离理由：A 的安全性靠"绝不真删"，B 的效率靠"绕过回收站"。合到一个模块里，
早晚会有人为了省事让 A 复用 B 的实现，那一次就是用户数据的终点。
`tests/test_guardrails.py` 断言 `scratch.py` 里不出现 `import action`。

白名单护栏 `_assert_purgeable()`，四条逐条抛 `PurgeRefused`：

1. 目标不存在 → 拒绝；
2. 目标是白名单根目录本身 → 拒绝；
3. 路径不在白名单之下 → 拒绝；
4. 目标是符号链接 / 目录联接 → 拒绝。

`ALLOWED_ROOTS = (".scratch",)`，只此一个。真删实现是自研后序遍历 +
`cmd /c del` / `cmd /c rd`：实测 `os.unlink`、`shutil.rmtree`、
PowerShell `Remove-Item`、`SetFileInformationByHandle(POSIX)` 全都走回收站，
`cmd /c del` 是唯一可行的真删方式。

因为两者不共享任何函数，`scratch.py` 自带一份 `human()`，
与 `infra.human_bytes()` 重复。看到这个重复不要去合并，那等于把两条删除路径
重新连起来。

### 3.1 三栏布局

```
┌─ toolbar ────────────────────────────────────────────────────────────┐
│ [扫描源 ▸ 浏览…] [档位▾ 说明] [相似度 ──○──] [开始扫描] [主题▾]        │
├─ 左栏 190 ─┬─ 中栏（网格，拉伸）────┬─ 右栏 350 ─────────────────┤
│ 分组筛选    │  QListView            │  预览大图（PreviewPane）      │
│ （单选）    │  GroupDelegate 画卡片 │  ══ 可拖的 QSplitter ══      │
│ 保护规则×3  │                       │  标题 / 焦点 / 详情 / 理由     │
│ 缩略图大小  │                       │  [设为保留][标记删除][删除…]   │
│ 滑块 64–256 │                       │  [全部按推荐裁决][撤销所有裁决]│
├─────────────┴───────────────────────┴──────────────────────────────┤
│ StageProgress（多段进度） 状态 · 计数 [暂停] [导出报告…] [撤销上次删除] [执行删除…] │
└────────────────────────────────────────────────────────────────────┘
```

- 左栏是 `PanelSurface`（自绘渐变 + 圆角 + 投影），**不是**一块和背景糊在一起
  的空白。侧栏品牌行（`● ImgDedup`）已移除：标题栏已经写着程序名，
  侧栏再来一遍是纯噪音。`BrandDot` / `BrandText` 两个类保留（截图脚本在用），
  只是 `window.py` 不再 import。
- **筛选是单选**（`SingleSelection`），「全部」或某一个分类。
  原先那套「全部 ⟺ 所有分类都勾选」的三级联动已经整体删除。
- **三条保护规则是只读展示**（`setEnabled(False)`），界面上不提供关闭入口。
- 中栏只有 `QListView`，**不再套竖向 splitter**。网格用 Qt 原生虚拟化：
  `_GroupListModel` 只做最薄适配（`rowCount` / `data(UserRole)`），
  QListView 只对可见行调 `data()`，所以 10 万行和 10 行开销一样。
- 右栏是竖向 `QSplitter`：上格预览 + 缩放控件（两者必须同格，否则缩放控件会被
  单独拖走），下格信息 + 按钮。`setChildrenCollapsible(False)` 对 QSplitter
  **不生效**，必须对每个子控件再 `setCollapsible(i, False)` 一次 —— 否则
  预览框会被拖没，用户找不到也恢复不了。

### 3.2 删除入口只有一个通道

界面上有 4 个调用点，全部汇到 `_delete_paths_now()`：

1. 底栏「执行删除…」→ `on_delete()`（批量）
2. 右栏「删除选中的这一张…」→ `_delete_of_selection()`
3. 右键「立即删除这一张…/这 N 张…」
4. 右键「删除本组其余全部」

汇合点是 `ask_delete` 询问去向 → `action.plan_from_paths` 过五条不变量 →
`action.execute` 写 manifest。**以后给界面加删除入口，复用这条路径，别另开通道。**

### 3.3 几个私有方法在解决什么

| 方法 | 解决的现象 |
|---|---|
| `_sync_view_width()` | `resizeEvent` 早于 `set_rows()`，按 0 行算列数 → 缩略图只排一列、右边大片空白 |
| `_sync_gradient()` | `apply_theme()` 在 `MainWindow()` 之前调用，自绘控件那时还不存在 → "按钮是琥珀的、背景还是薄荷的" |
| `_on_wheel()` | Qt `ScrollPerPixel` 下 singleStep = 一整行卡片高（112 px 时约 1018 px），× `wheelScrollLines(3)` → 一格滚 3000 px、一次见底 |
| `_on_thumb_size_changed()` | 只改 delegate 尺寸不重布局 → 新尺寸的缩略图画到下一张卡片头上 |

### 3.4 为什么图标与 cv2 检查在 `_entry_symbols.py`

PyInstaller 的**入口脚本不进 `PYZ.pyz`**，放在 `__main__.py` 里的任何符号
`dev/check_frozen.py` 都扫不到（它只扫 PYZ）。所以真身必须放普通模块，
入口只做转发。同理，`--interact-test` 用的 `dev.click_frozen` 是动态导入，
静态分析看不到，必须写进 spec 的 `hiddenimports`。

## 4. 一次扫描的完整数据流

阶段顺序（`worker.STAGE_ORDER`）：
**遍历 → 元数据 → 短指纹 → 全量哈希 → 感知特征 → 语义 → 聚类**

```
用户点「开始扫描」
   ↓ window.on_start  → 从 MODES 取档位参数
ScanWorker(QThread).run()
   ├─ 遍历       scan.walk()                 → FileEntry 列表
   ├─ 元数据     decode.probe_meta()          → width/height/fmt/frames
   │              按 estimate_decode_bytes 过 MemGate 限流
   ├─ 短指纹     feature.quick_hash()         → 大小分桶 + 短指纹筛候选
   │              【快速档到此为止：full_hash_skipped / perceptual_skipped】
   ├─ 全量哈希   feature.full_hash()          → group.exact_groups()
   ├─ 感知特征   feature.extract()            → group.perceptual_groups()
   │              超大图（>1 亿像素）跳过
   ├─ 语义       embed.ClipEncoder.encode()   → embed.cosine_groups()
   │              【只有深度档；超 max_group 的分量进 oversized】
   └─ 聚类       model.build_rows()           → GroupRow 列表（UI 行）
                 每个文件只进"最强"的那一类：精确 > 近似 > 语义
                 （字节相同的图必然也满足感知判定，不排除就会被报两遍，
                   而"可释放空间"会被算两遍 —— 实测虚高 1.94 倍）
   ↓ finished_ok(rows, meta)
window._on_finished → model.set_rows() → _sync_view_width()
```

三档的真实差异收敛在 `worker.MODES` 一张表里，UI 文案、`on_start()` 参数、
流水线分支**全部从它派生** —— 避免"下拉框写一套、实际跑另一套"。

| key | 名称 | 做什么 | 会漏掉 |
|---|---|---|---|
| `fast` | 快速 | 只比「文件大小 + 头尾各 64 KB 指纹」，不读全文件、不解码像素 | 重压缩 / 改尺寸 / 加过水印的近重复 |
| `balanced` | 精确（默认） | 加全量哈希 + 感知特征 | 构图相似但画面内容不同的图 |
| `deep` | 深度 | 加 CLIP 语义向量余弦聚类 | 语义模型本身理解不了的抽象相似 |

进度是**多段**的（`StageProgress`），不是一根总进度条：一根总条在"最后一公里"
只能靠 99% 卡住来表达"还在算"。扫描期间可暂停、可取消；
`cancel()` 会**同时置位 `_pause`**，否则线程卡在 `_pause.wait()` 上退不出来。

## 6. 开发脚本 `dev/`

`dev/` 不进发布产物。分四类：

### 6.1 门禁（CI 会跑）

| 脚本 | 做什么 | 退出码 |
|---|---|---|
| `check_no_network.py` | 把 `socket.create_connection` / `urllib.request.urlopen` 换成会抛异常的桩（放行回环与 `file://`），跑全量测试 | 0 全绿；1 = 有测试联网，或测试本身红了 |
| `check_artifacts.py` | 产物级验收：跑 exe `--selftest` + 扫 `_internal` 里的外置组件 / AGPL 红线 + 报体积 | 0 / 1 |
| `check_frozen.py` | 归档级符号校验：读 exe 内嵌的 PYZ，逐项确认关键符号在包里。`--absent <符号>` 做反向断言 | 0 / 1 |

`check_no_network.py` 与 `check_fresh_clone.py` 都**不动任何文件**：
早先的做法是"临时把 `resources/models` 改名藏起来"，进程被强杀时（SIGTERM
不走 `finally`）目录就留在改名状态 —— 这个坑真踩过两次。

### 6.2 门禁（本机跑，不在 CI）

| 脚本 | 做什么 | 退出码 |
|---|---|---|
| `check_fresh_clone.py` | 按 git 的口径把文件拷到临时目录，在干净环境里跑全量测试 | 0 / 2（`.gitignore` 漏了大目录）/ 其它 |

**为什么 CI 里不跑它**：CI 的 `actions/checkout` 拿到的东西本身就是"新克隆"
（只有被跟踪的文件），所以它验的就是 CI 环境。它的价值在**推之前在本机跑**：
本机有模型、有 `dist/`、有缓存，会把"只在干净环境才暴露"的问题盖住。

它抓到过一次代价很大的事故：`_guard_deep_mode` 原本挂在 `currentIndexChanged`
上（程序化 `setCurrentIndex` 也会触发）→ 测试把档位设成「深度」时弹出模态
对话框、没人点 → 整套测试挂死十几分钟。本机因为模型在位从来不触发，CI 上
就是挂到 job 超时。

它还会用 `IMGDEDUP_MODEL_DIR` / `IMGDEDUP_TEST_LIBRARY` 把真实模型缓存与
真实图库都指到空目录 —— 不指走的话，依赖它们的测试在临时目录里照样能跑，
这条门禁就模拟不出 CI。

### 6.3 打包与取外置组件

| 脚本 | 用途 | 关键参数 |
|---|---|---|
| `make_installer.py` | 产出免安装版 + 安装包 | `--build`（两个都出）/ `--portable`（只出免安装版，体检也只看那一半）/ 不带开关（只出安装包）/ `--check`（只体检） |
| `make_icon.py` | 从原图生成 `icon.ico` / `icon.png` | `--src <图片>` / `--out <目录>` |
| `fetch_cv2.py` | 准备外置 cv2 | `--download`（从 PyPI）/ `--out` / `--zip` |
| `fetch_model.py` | 取外置 CLIP 模型 | `--force` / `--fp32` / `--out` / `--zip` |
| `purge.py` | 路径 B 入口：真删开发垃圾 | `--dry-run` / `--keep-scratch` |

两个默认值的**语义不同**，发布流程依赖这一点，别以为它们对称：

- `fetch_cv2` 不给 `--out` → `dist/ImgDedup/extra`

所以 `python -m dev.fetch_model --zip` 不会污染 `dist/ImgDedup`。

`make_installer --build` 的**退出码就是体检结论**（早先写死 `return 0`，
release 那一步照样绿，坏掉的安装包会被直接发到 Release 页）。
体检项：主程序存在 + PE 里嵌了图标、安装包存在 + 图标、`_internal` 下没有
`cv2.pyd`、`extra/` 已建出。读图标走
`LoadLibraryExW(LOAD_LIBRARY_AS_DATAFILE)` + `EnumResourceNamesW`：
自研 PE 解析出过假阴性（明明嵌了图标却报 `None`）。

## 7. 质量门禁

| 门禁 | 抓什么 | 什么时候跑 |
|---|---|---|
| 全量单元测试 | 功能回归，含未定义名字的静态检查 | 每次改动 |
| 断网门禁 | "顺手下载模型或 cv2"的代码路径 | 改了任何可能联网的代码 |
| 干净克隆门禁 | 只在干净环境才暴露的问题 | 推之前 |
| 产物自检 | 打包后底层库能不能加载、核心与界面能不能导入、外置组件情况 | 每次打包后 |
| 产物红线扫描 | 模型 / cv2 有没有被打回包、有没有 AGPL 组件 | 每次打包后 |
| 归档符号校验 | 产物里装的是不是**本次**的代码，而不是上一轮的旧包 | 动了启动链路或修了闪退类 bug 之后 |
| 文档数字一致性 | 文档里的测试项数与实际对不上 | 每次改动 |
| 文档链接与锚点 | 相对链接失效、锚点对不上标题、代码围栏是奇数 | 每次改动 |

两条铁律，实施时不要绕：

- **崩溃类 bug 用子进程 + 退出码测。** 进程内的断言抓不到 Qt 的 `abort()`，
  闪退没有回溯，退出码是唯一判据。
- **修了 bug 要做注入验证**：把修复改坏，确认测试真的会红。改不红的测试等于没测。

### 7.1 CI 与发布的分工

`ci.yml`（分支推送 / PR / 手动）：三个 job —— 单元测试、打包冒烟、断网门禁。

`release.yml`（推 `master` / tag `v*` / 手动）：

```
gate（定 tag + 查这个版本的 Release 在不在）
  └→ test（全量测试，needs: gate）
       └→ release（needs: gate, test）
            ├ 校验 tag 与 __version__ 对得上
            ├ 装 Inno Setup → make_installer --build（退出码即体检结论）
            ├ check_artifacts.py（自检 + 红线）
            ├ check_frozen.py（归档符号）
            ├ 打免安装版 zip（必须在放外置组件之前）
            ├ 取 cv2 / 模型并打 zip
            ├ 生成 SHA256SUMS.txt（顺带断言产物齐全）
            ├ 远端没有 v<版本> 就补建 tag；有就核对它指向本次提交
            └ gh release create / upload --clobber
```

推分支也发版，但只在 `__version__` 变了的时候：`gate` 先拿 `v<__version__>`
去查 Release，查到了就把后两个 job 整个跳过。一个版本号只对应一份二进制，
`SHA256SUMS.txt` 才有意义；顺带也省掉每次 push 都要下一遍 170 MB 外置组件。
挡住的只有"推分支"这一种情况 —— 推 tag 和手动触发是明确的发布意图，一律
构建，半截的 Release 正是靠重跑这两条路把附件补齐的。

几处这么安排的理由：

- **tag 只在一处定**（`gate`）：推 tag 时用它自己，推分支时按 `__version__`
  推成 `v<版本>`。`release` job 只负责核对，不再自己推一遍 —— 同一条规则
  写两份，迟早漂移成两套判据。
- **tag 推送不触发 `ci.yml`**（那个只监听分支），所以发布路径必须自己跑
  产物门禁。少了它们，一个从没走过打包冒烟的 commit 打上标签就能发出去。
- **`--verify-tag`**：没有它时 `gh release create` 会照着默认分支自己造一个 tag，
  手动触发填错名字就会造出一个莫名其妙的 tag。代价是推分支那条路得自己把
  新 tag 推上去 —— 放在构建之后推，免得失败时留下"有 tag、没 Release"的半截状态。
- **`--clobber` + 先探测**：重跑要能补齐附件，而不是因为"Release 已存在"报错。
- **`cancel-in-progress: false`**：取消一个正在上传的发布，会留下
  "Release 建了、附件缺一半"的半截状态。
- 每个 job 都有 `timeout-minutes`：没有它时 GitHub 给 6 小时默认值，
  日志里只剩一行超时，看不出卡在哪。
- `permissions` 收窄到最小：CI 只读，只有 release job 拿 `contents: write`。

## 9. 编码约定（硬规则）

这些不是风格偏好，违反会直接出故障。

### 9.1 行尾与编码

**行尾统一 LF，只有 `启动ImgDedup.bat` 是 CRLF** —— 由 `.gitattributes` 钉住：

```
* text=auto eol=lf        # 仓库里存 LF，检出也是 LF
*.bat text eol=crlf       # 唯一的例外；更具体，所以覆盖上面那条
```

`eol=lf` 不能省。只写 `text=auto` 时，检出时的行尾由每台机器的
`core.autocrlf` 决定 —— 而 Git for Windows 默认把它设成 `true`（**system 级**），
于是同一个 commit 在这台机器上克隆出 CRLF、在那台上是 LF，不可复现；
`git add` 还会为每个文本文件各打一条
"LF will be replaced by CRLF the next time Git touches it" 警告。
钉死之后，工作区行尾与机器设置无关。

所以正常情况下**不需要手工照顾行尾**。但改文件仍然建议**字节级读写**
（`read_bytes().decode()` / `write_bytes(s.encode())`）：文本模式
`open(..., "w")` 在 Windows 上会按 `os.linesep` 写回，
碰到 `.bat` 这种"行尾有语义"的文件就直接出事。

`启动ImgDedup.bat` 必须是 **GBK(cp936) + CRLF + 无 BOM**：cmd 遇到 LF 会解析
失步（一行被从中间劈开、后半截被当命令执行，表现是"双击没反应"）。
**不能用编辑器直接保存**（只能写 UTF-8 会把 cmd 解析搞失步）。
验证方式是做一份把 `start` / `pause` 换成 `echo` 的 dry-run 副本，
用 cmd 跑、按 GBK 解码，断言 0 条解析错误 + 中文原样出现。
`tests/test_launcher_bat.py` 把这三条（编码 / 行尾 / 真解析）都钉住了。

### 9.2 单一来源

同一个事实只允许有一个落点。已经建立起来的：

| 事实 | 唯一来源 |
|---|---|
| 版本号 | `imgdedup_core/__init__.py` 的 `__version__` |
| 三档扫描模式的文案与参数 | `imgdedup_ui/worker.py` 的 `MODES` |
| 相似度默认阈值 | `imgdedup_core/embed.py` 的 `DEFAULT_THRESHOLD`（GUI 的 `SIM_DEFAULT_PCT` 必须等于它 ×100，有测试钉） |
| 图标尺寸列表 | `dev/make_icon.py` 的 `ICON_SIZES`（`test_packaging.py` 里那份期望值必须一致） |
| cv2 解包跳过规则 | `imgdedup_core/cv2_fetch.py` 的 `should_skip`（`dev/fetch_cv2.py` 委托给它） |
| 产物红线判据 | `dev/check_artifacts.py`（`ci.yml` 与 `release.yml` 共用） |

所以 `imgdedup_ui/__init__.py` 里**没有 `__version__`**。
它曾经有一份副本，而没有任何代码读它 —— 一份不读的副本唯一的作用
就是某天和真版本对不上。它也不能靠 `from imgdedup_core import __version__`
派生：那会让界面包在导入期拉进核心引擎，直接违反"启动路径不导入核心引擎"。

### 9.3 惰性导入

- `imgdedup_core` 里**不许顶层 `import cv2`**，一律走
  `from .opencv import lazy_cv2 as cv2`。缺组件时要给人话提示，
  而不是"窗口都建不出来"的闪退。
- `imgdedup_ui` 里对 core 的引用写在**方法内部或后台线程里**。
- `action.py` 里 `feature` / `group` 是函数内延迟导入。

### 9.4 Qt 的两个坑

- **弹对话框的代码不能挂在"程序化也会发"的信号上。** 用 `activated` 这类
  "只在用户操作时发"的，别用 `currentIndexChanged` 这类。否则测试 /
  CI 里没人点那个模态框，一路挂到 job 超时。
- **`QTimer` 依赖当前线程的事件循环。** 在 `threading.Thread` 里
  `QTimer.singleShot(0, ...)` 的回调**一次都不会触发**（后台线程没有事件循环）。
  要跨线程回主线程，用 `QThread` + 信号（Qt 的跨线程信号默认
  `AutoConnection → QueuedConnection`，天然把调用排进接收者的事件队列）。

### 9.5 断言要锚到真东西上

本仓库的注释比代码还多，`assertIn("某个词", 源码)` 很容易命中的是**注释**，
于是"把配置删掉、只留注释，测试照样绿"。已经踩过的：

- `assertIn("icon=str(ICON_ICO)")` 是 `icon=str(ICON_ICO),` 的子串，
  删掉那一行后仍然命中。
- `assertIn("--clobber")` 会被注释里的同一个词满足。

所以断言要么锚到带缩进 / 带调用形式的整行，要么**先剥掉整行注释**再断言
（`tests/test_release_pipeline.py` 的 `strip_comments()`）。

## 10. 踩坑清单

按主题整理。每条都对应代码或测试里的一段注释，动手前值得扫一眼。

### 10.1 文件系统与 Windows

- **`rm -rf` 走回收站，不是真删。** 删完 `df` 复测不变，就说明进回收站了。
  要真释放空间必须清空回收站；反过来，**删除是可撤销的**。
- **删硬链接不影响原文件本体**（链接计数 -1）。但**硬链接挡不住原地覆写**：
  `open(w)` / 编辑器保存这类"原地写"会把字节同时写进快照/链接。
  所以别把硬链接当版本控制。
- **`explorer /select,<路径>` 里 `subprocess` 的自动加引号会坏事。**
  `subprocess.Popen(["explorer", f"/select,{p}"])` 会被 `list2cmdline`
  按 MSVCRT 规则加引号，而 `explorer.exe` 不按那套规则解析 → 它忽略整个参数、
  打开默认的「文档」目录。正确写法是自己拼一整条命令行字符串：
  `subprocess.Popen(f'explorer /select,"{target}"', shell=False)`。
  `shell=False` + 字符串时 `CreateProcess` 会原样传给子进程，就是要的效果。
- **`os.stat` 的 `st_dev` / `st_ino`** 在 Windows 上分别是卷序列号与文件索引，
  够用，不需要 ctypes。
- **不要用字符串比较路径。** `Path.resolve()` 在 Windows 上可能返回 8.3 短名
  （`C:\Users\LIGHTN~1\...`），而调用方给的是长名，两者指同一目录但字符串不等。
  典型症状是"刚写进去的记录立刻查不到"这种纯静默故障。
  统一走 `normcase` + `normpath`（必要时再 `GetLongPathNameW`）规整后再比。
- **`shutil.rmtree` 会跟着目录联接删到链接目标。** Windows 的联接在
  `os.scandir` 里仍报为目录。`scratch.py` 因此自研后序遍历，绝不进入
  reparse point。
- 删文件报 `Device or resource busy` 时，用 Restart Manager
  （`rstrtmgr.dll` 的 `RmStartSession` / `RmRegisterResources` / `RmGetList`）
  查占用者。扫进程模块（`Get-Process | %{$_.Modules}`）只能看到 dll/exe，
  **看不到数据文件句柄**，会得出"没有进程占用"的错误结论。

### 10.2 打包

- `SPECPATH` 是 spec **所在目录**，不是它的父目录：直接用 `Path(SPECPATH)`。
- `excludes` 只过滤 Python 模块，**DLL / pyd 要另按文件名过滤**。
  实测：不裁 227.5 MiB，裁完 190.5 MiB（差 37 MiB，主要是 Qt6Qml / Quick /
  Designer 那一堆和 `opengl32sw`）。裁剪只按文件名关键字匹配，
  所以新增 Qt 模块时记得看一眼 `EXCLUDE_BINARIES_KEYWORDS`。
- `pypdfium2` 按 `Path(__file__).parent / "pdfium.dll"` 找 DLL，
  所以那两个包必须以**真实 .py 文件**落到 `_internal/`（见 spec 的
  `module_collection_mode`），且 `pdfium.dll` 要显式 `collect_data_files`。
- 排除 cv2 之后要显式收 `numpy.core.multiarray`：`cv2/__init__.py` 里有
  `import numpy.core.multiarray`（numpy 1.x 时代的旧路径），numpy 2.x 里它
  只是个小垫片，静态分析不会收。表现为"外置 cv2 放对了位置却还是加载失败"。
- Inno 的路径**一律用绝对路径**，由 ISCC 的 `/D` 传入。Inno 在不同编译阶段
  cwd 并不一致：实测 `OutputDir=..\dist\installer` 被解析成
  `E:\Develop\items\dist\installer`（少一层），`SetupIconFile=..\resources\icon.ico`
  直接报"系统找不到指定的路径"。
- `Path.write_text` 会把串里的 `\n` 再转成 `\r\n`：串里已经手写了 `\r\n` 的话
  会变成 `\r\r\n`（33 个裸 CR），记事本打开每行多一个空行。
  用 `write_text(..., newline="")`。
- 打包前先 `tasklist | grep -i ImgDedup`：老进程占着产物目录时，
  COLLECT 会产出新旧混合的目录。

### 10.3 Qt / QSS

- **QSS 不支持 `box-shadow`。** 萤火光点与卡片投影只能自绘
  （`widgets.glow()` 用 `QRadialGradient` 模拟）。别在 `build_qss()` 里写阴影。
- **QSS 的 `qlineargradient` 语法与 CSS 的 `linear-gradient` 完全不同**，
  不能照抄。
- **`QComboBox` 弹出列表的选中行底色 QSS 上不了色。** 只要 `QComboBox` 控件
  本身命中任意 QSS，popup 的选中行就不采纳 `::item:selected { background }`，
  也不采纳 `palette.Highlight`（逐像素实测过 5 种写法，全部无效）。
  只能用自绘 delegate（`widgets.ComboItemDelegate`）。
- **QSS 选择器别写裸 `QListView`。** `QComboBox` 的弹出列表 view 是
  `QListView` 的子类，裸选择器会把"背景透明 + 无边框"套到弹出列表上，
  于是弹出的那块底是透明的，看起来像"列表里有个空白选项"。
  要限定成 `QListWidget`。
- **`setChildrenCollapsible(False)` 对 `QSplitter` 不生效**，
  必须对每个子控件再 `setCollapsible(i, False)`。
- **`PreviewPane.wheelEvent` 必须 `accept()`**：外层 `QSplitter` / 滚动区
  默认会把滚轮吞掉去滚自身。
- **切主题时必须同时改 `widgets.py` 里的 `QColor` 常量**，并
  `viewport().update()` 重绘 —— 否则出现"按钮变薄荷了、缩略图边框还是蓝的"。
  而且要**就地 `setRgb`**，不能换对象：delegate / BrandDot / StageProgress
  已持有引用。
- `setNamedColor` 在 PySide6 6.11 已废弃，用 `setRgb`。
- `ThumbCache._on_loaded` 是**从工作线程直接调用**的（不是槽）。窗口先关、
  任务后完成时对象已销毁，会刷 `RuntimeError: Signal source has been deleted`。
  加 `shiboken6.isValid(self)` 守卫。

### 10.4 性能与体积

- **不要给列表加 drop-shadow**：上千个 item 逐个带阴影，滚动会掉帧。
- **不要在 `paint()` 里加载图片。** 缩略图走异步缓存
  （`ThumbCache` + `QThreadPool`），未命中先画占位、不阻塞。
- **预览框用独立 `ThumbCache`**（1024 px、容量 12），不与网格共用：
  共用的话逛一圈预览就能把网格那 800 张小图挤光。
- 大图解码是百毫秒级（大 JPEG 的熵解码必须解完全部系数），
  所以预览必须异步 + token 作废（快速连点时先发的任务后回来，
  会把新图覆盖成旧图）。
- 截图 / 探针脚本里**必须用真的 `QEventLoop` 等解码**，不能空转
  `processEvents()`：后者驱动不了 `QThreadPool`，会得出"图没加载出来"的
  **错误结论**。

### 10.5 测试自身

- **写断言前先 grep 真实函数签名**，不要凭印象。
- **给某个状态加了不变量之后，测试不能再手工摆状态去构造它。**
  实例：给筛选面板加了「『全部』勾选 ⟺ 所有分类都勾选」之后，三条旧测试用
  `setCheckState` 逐个摆出「全部勾 + 分类不勾」—— 这在新的不变量下是**到不了
  的状态**，于是集体假失败，看起来像"改坏了"。改用会真正产生该状态的触发路径。
- **"参数对不对" ≠ "能不能跑"。** 凡是有"提前返回"的分支必须端到端跑一次：
  `fast` 分支最初写在 `cand` 定义之前，单元测试只断言了
  `ScanWorker(..., mode="fast").mode == "fast"`（参数完全正确），
  真扫一遍却立刻 `UnboundLocalError`。
- **`python - <<'PY'` 的 heredoc 在本机 Git Bash 下会把内容里的反斜杠转成 `/`。**
  校验正则因此永远不匹配，**误报"修复没落盘"**，差点去改一段完全正确的代码。
  凡字符串里含反斜杠（正则、Windows 路径、转义），一律写成脚本文件再跑。
  引申判据：**"校验命令自己坏了"和"被校验的东西坏了"长得一模一样** ——
  报 FAIL 时先把中间值 `repr` 出来看一眼。

### 10.6 界面状态同步

这几条都是"主界面变了、它没变"这一类半截状态，改界面时容易踩。

- **筛选重建不能把用户的选择打回「全部」。** `_rebuild_filters()` 每次裁决都会
  被触发，无脑重置成「全部」的话，用户选的分类会被悄悄打回，
  表现为"我刚选了近似重复，改了一张图又跳回全部"。必须保留当前选择，
  只有选中的分类在新结果里不存在时才回落「全部」（例如关掉语义层重扫后
  `semantic` 组消失）。`test_rebuild_preserves_user_selection` 与
  `test_rebuild_when_selected_kind_disappears` 各钉一头。
- **取消选中要显式清空预览。** `_clear_selected()` 会走 `_on_current_changed()`，
  而后者只看"当前行"在不在；取消的是**缩略图级**选中、当前行仍在，
  于是不走清空分支，预览停在那儿显示一张已经没被选中的图。
  要在 `_clear_selected()` 里显式 `preview.show_path(None)`。
- **预览缩放只改显示倍率，`QPixmap` 一个字节不动**（缩到 0.2x 再放回 1x 画质无损）；
  缩放要**以光标为锚点**（侧栏窄，不锚定的话放大后想看的细节立刻跑出可视区，
  用户只能反复"放大 → 找不到 → 缩小"）；放大后拖动平移要用 `_clamp_pan()`
  保证图边不越过可视区中线。
- **断言控件归属要沿 `parentWidget()` 链往上查**，不能只断言
  `splitter.widget(0) is x`：万一有人把它也 `addWidget` 到别处，
  Qt 会静默把它从原位置摘走，而 `widget(0)` 可能仍然命中。

## 11. 打包与发布

### 11.1 产物形态

| 产物 | 内容 |
|---|---|
| `ImgDedup-portable-win64.zip` | 免安装版（PyInstaller onedir，解压后 190.5 MiB：exe 7.3 + `_internal` 183.2） |
| `ImgDedup-<版本>-setup.exe` | Inno Setup 安装包（lzma2/max 压完 54.1 MiB），装到 `%LOCALAPPDATA%\Programs\ImgDedup`，全程不弹 UAC |
| `cv2-win64.zip` | 外置组件（86 MB） |
| `models-*.zip` | 外置 CLIP 模型（85 MB） |
| `SHA256SUMS.txt` | 上面几个的校验和 |

**顺序很重要**：先打包 → 再打免安装版的 zip → 最后才取外置组件。
反过来做的话 cv2/模型会被卷进免安装版的 zip 里（多 171 MB），
整个"外置"设计就白做了。

安装包会连 `extra\` 一起删（`[UninstallDelete]`）：用户往里面放的 cv2 / 模型
最多 171 MB，那是 Inno 没安装过的文件，不写这条卸载后会剩一个巨大的孤儿目录
（实测卸载后 `extra\cv2\` 里 103 个文件原封不动）。代价是重装后要重新下载。

### 11.2 许可

本仓库自己的代码是 MIT。产物里含第三方组件，其中 **PySide6 与 libvips 是
LGPL-3.0**，分发二进制时要附许可全文并保证用户可以替换这两个库
（PyInstaller 打的是独立 DLL，这条天然满足）。

**产物里不能有 AGPL 组件。** PDF / AI 解码选的是 `pypdfium2`
（BSD-3-Clause / Apache-2.0，随包分发，8 MB）。

完整清单与分发义务见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)，

## 12. 常见改动怎么做

### 改一个扫描档位

1. 改 `imgdedup_ui/worker.py` 的 `MODES`（文案 + 参数）；
2. 改 `ScanWorker._run()` 里的流水线分支（注意"提前返回"的分支要端到端跑一次）；
3. 跑 `tests/test_preview_zoom_anim.py::TestScanModes` 与
   `TestFastModeEndToEnd`；
4. `dev/probe_modes_e2e.py` 真扫一个图库，确认两档的组数与耗时确实不同。

### 加一种图片格式

1. 在 `decode.py` 的 `VIPS_EXTS` / `PILLOW_EXTS` / `PDF_EXTS` / `HEADER_EXTS`
   里归类；
2. 魔数能识别的话补进 `_MAGIC`；
3. 如果默认瀑布顺序不对，在 `_META_PLAN` / `_THUMB_PLAN` 里加一条 ——
   顺序要**实测**决定（跑 `dev/run_cli.py` 的格式矩阵，看耗时与成功率）；
4. `THIRD_PARTY_NOTICES.md` 里补许可。

### 改主题

见 [流萤主题美化设计方案.md](流萤主题美化设计方案.md)。两条不能破的：

- 裁决三态（`KEEP` / `DEL` / `UNDECIDED`）与分类徽章色**不随主题变**；
- 切主题必须同时刷新 `widgets.py` 的 `QColor` 常量（就地 `setRgb`）+ 重绘。

改完跑 `tests/test_theme.py` 和 `dev/shot_themes.py`。

### 加一个删除入口

**不要另开通道。** 复用 `window._delete_paths_now(paths, source=...)`：
它负责 `ask_delete` 询问去向 → `action.plan_from_paths` 过五条不变量 →
`action.execute` 写 manifest。

### 加一个质量门禁

1. 写成 `dev/check_xxx.py`，**退出码就是结论**（0 通过、非 0 失败）；
2. 在 `tests/` 里给它加测试，并做**注入验证**（改坏它，确认测试会红）；
3. 挂进 `ci.yml`（分支）和 / 或 `release.yml`（发布前）；
4. 在本文件第 7 节的门禁表里补一行。
