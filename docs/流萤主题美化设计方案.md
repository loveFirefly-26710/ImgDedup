# 一、设计

## 1. 一句话结论

**以固定 hex 色阶为骨、以萤火光点为魂，做一套克制的浅色主题。**
提供 **5 套预设主题色**切换，不做 hue 滑块。

理由：ImgDedup 是**工具软件** —— 用户 90% 的时间在盯着图片本身做判断，
界面应该"存在但不抢戏"。oklch 全站派生 + hue 滑块那套是给「内容即主角」的
展示型站点准备的，用在去重工具上会让界面比图片还花，反而降低判断效率。

## 2. 色值 Token

### 2.1 主色阶（流萤·薄荷）

| Token | 色值 | 用途 |
|---|---|---|
| `accent` | `#14B8A6` | 主按钮底、激活态、进度条填充、焦点环 |
| `deep` | `#0D9488` | 主按钮 hover / pressed、链接文字、选中环 |
| `soft` | `#DCF5EF` | 选中行底色、徽章底、进度条已过部分 |
| `line` | `#D9ECE6` | 分隔线、卡片描边（带一点点青，比纯灰暖） |
| `bg` | `#F6FBF9` | 窗口底色（暖白偏薄荷） |
| `card` | `#FFFFFF` | 卡片 / 输入框底 |
| `text` | `#1D2B28` | 正文（比纯黑柔，带极轻的青绿倾向） |
| `muted` | `#6F8A83` | 次要文字、说明、禁用态 |
| `hover` | `#8FDCD0` | 悬停描边（`accent` 的浅一档） |

### 2.2 裁决三态（**不随主题变**）

这三色是**语义色**，不是装饰色，必须保持"红 = 危险 / 绿 = 安全"的通用直觉。

| Token | 色值 | 用途 |
|---|---|---|
| `KEEP` | `#1D9E75` | 保留。通用安全绿，不能改成主题色，否则会跟「未裁决」混淆 |
| `DEL` | `#D94B4B` | 待删。比纯红沉一档，和 `accent` 同屏更协调 |
| `UNDECIDED` | `#B4B2A9` | 未裁决。中性暖灰，明确表达"还没决定" |

**`KEEP` 与 `accent` 必须能一眼区分**：`#1D9E75`（偏黄绿）vs `#14B8A6`（偏青），
色相差约 40°，在缩略图边框这种细线上仍能分辨。

### 2.3 分类徽章（**不随主题变**）

| 分类 | 底色 | 文字 |
|---|---|---|
| `exact` 精确 | `#E1F5EE` | `#0F6E56` |
| `perceptual` 感知 | `#FAEEDA` | `#854F0B` |
| `semantic` 语义 | `#E6F1FB` | `#185FA5` |
| `cluster` 聚类 | `#FCEBEB` | `#A32D2D` |

这四个色是**分类标识**：用户靠颜色区分分组类型，改掉就失去肌肉记忆，
而且它们与主色没有冲突。

### 2.4 五套预设

| 名称 | key | accent | deep | soft | 气质 |
|---|---|---|---|---|---|
| 流萤·薄荷（默认） | `mint` | `#14B8A6` | `#0D9488` | `#DCF5EF` | 流萤本体，青绿冷光 |
| 琥珀·余烬 | `amber` | `#F59E0B` | `#D97706` | `#FEF3E2` | 暖橘，长时间夜间使用护眼 |
| 樱粉·梦境 | `sakura` | `#EC7FA9` | `#DB2777` | `#FCE7F3` | 柔粉，弱化工具感 |
| 星穹·蓝 | `starlight` | `#5B8DEF` | `#3B6FD4` | `#E3EDFC` | 最"专业软件"的一套 |
| 极光·紫 | `aurora` | `#8B7CF6` | `#6D5CE7` | `#EDE9FE` | 冷紫，偏设计感 |

切主题时只换 accent 三件套 + `line` / `bg` / `card` / `text` / `muted` / `hover`；
语义色与徽章色一律不动。

### 2.5 自绘专用字段

QSS 给不了渐变，所以每套主题还带一组只给自绘控件用的字段：

| 字段 | 形式 | 用在哪 |
|---|---|---|
| `grad_a` / `grad_b` | hex | 主按钮的三段渐变（浅 → 主 → 深） |
| `glow` | `"R, G, B"` 字符串 | 光晕，自绘时拼 `rgba()` |
| `bg_top` / `bg_mid` / `bg_end` | hex | 主背景的三段渐变 |
| `shadow` | `"R, G, B"` 字符串 | 卡片与面板的柔和投影 |

**`glow` 与 `shadow` 是 RGB 三元组字符串、不是 hex**，因为它们只用于自绘时
拼 `rgba(...)`。`apply_theme()` 里对它们有单独的解析路径（见 8.4）。

## 3. QSS

### 3.1 生成方式

`theme.build_qss(key)` 按主题拼出整份 QSS，运行时 `app.setStyleSheet()` 换上。
样式必须是参数化的：主题要能运行时切换，就不能把 QSS 内联在入口里。

```python
THEMES = {
    "mint":  {"accent": "#14B8A6", "deep": "#0D9488", "soft": "#DCF5EF",
              "line": "#D9ECE6", "bg": "#F6FBF9", "card": "#FFFFFF",
              "text": "#1D2B28", "muted": "#6F8A83", "hover": "#8FDCD0", ...},
    "amber": {...}, "sakura": {...}, "starlight": {...}, "aurora": {...},
}
```

### 3.2 关键取值与理由

| 项 | 取值 | 理由 |
|---|---|---|
| 控件圆角 | `8px` | 小控件用更大圆角会显得像胶囊，反而怪 |
| 卡片 / 面板圆角 | `14px` | 大块面用大圆角才柔，边界不那么硬 |
| 描边色 | `line`（`#D9ECE6`） | 带极轻青色，整屏有统一的"流萤感"，比纯灰暖 |
| 窗口底色 | `bg`（`#F6FBF9`） | 暖白偏薄荷 |
| 焦点态 | `border-color: accent` | 键盘 tab 到哪个输入框必须一眼看出来 |
| 网格底 | `#FFFFFF` | 卡片是白的，网格底也白才连成一片 |
| 主按钮 | `qlineargradient` 三段 + 白字 + `font-weight: 600` | 纯色按钮会显得很平，加一层光源方向 |
| 危险按钮 | 白底 + `DEL` 描边 + `DEL` 文字，**永不实心** | 实心红色大按钮会被误点 |
| 滚动条 | 透明轨、圆角 handle、**无箭头** | 去掉 Qt 默认样式的"Windows 98 味" |
| 菜单 | 卡片底 + 10px 圆角 | 和整体圆角语言一致 |

### 3.3 QSS 的三条硬限制

这三条决定了"哪些东西必须自绘"，是设计的边界条件：

1. **不支持 `box-shadow`。** 光晕与投影只能自绘
   （`widgets.glow()` 用 `QRadialGradient` 模拟，`PanelSurface` 自己画两层）。
   `QGraphicsDropShadowEffect` 能做，但对大量 item 有性能风险，**不用在列表上**。
2. **`qlineargradient` 的语法与 CSS 的 `linear-gradient` 完全不同**，不能照抄。
3. **`QComboBox` 弹出列表的选中行底色上不了色。** 只要 `QComboBox` 控件本身
   命中任意 QSS，popup 的选中行就不采纳 `::item:selected { background }`，
   也不采纳 `palette.Highlight` —— 逐像素实测过 5 种写法，全部无效。
   只能用自绘 delegate（`widgets.ComboItemDelegate`）。见 8.5。

## 4. `widgets.py` 的 `QColor` 常量

### 4.1 为什么是常量而不是 QSS

`widgets.py` 里的自绘控件（delegate、`PreviewPane`、`StageProgress`、
`BrandDot` …）在 `paintEvent` 里直接读这些 `QColor` 常量。它们**不读 QSS**：
QSS 管的是 Qt 内置控件的外观，自绘代码读不到它。

代价是切主题时**必须同时刷新这些常量并重绘**（`viewport().update()`），
否则会出现「按钮变薄荷了、缩略图边框还是蓝的」这种半截状态。
`theme.apply_theme()` 负责把这件事做完整。

### 4.2 常量清单

| 常量 | 取值（mint 主题下） | 用途 |
|---|---|---|
| `C_CARD` | `#FFFFFF` | 卡片底 |
| `C_BORDER` | `#D9ECE6` | 卡片描边 |
| `C_TEXT` / `C_TEXT_DIM` | `#1D2B28` / `#6F8A83` | 正文 / 次要文字 |
| `C_KEEP` / `C_DEL` / `C_UNDECIDED` | `#1D9E75` / `#D94B4B` / `#B4B2A9` | 裁决三态（恒定） |
| `C_PLACEHOLDER` | `#EDF6F3` | 缩略图未加载时的占位块 |
| `C_FOCUS` | `#0D9488` | 选中环（用 `deep`，理由见 4.3） |
| `C_HOVER` | `#8FDCD0` | 悬停描边 |
| `C_CARD_FOCUS` | `#DCF5EF` | 分组卡焦点描边 |
| `C_FOCUS_WASH` | `rgba(13,148,136,26)` | 焦点洗色覆盖 |
| `C_ACCENT` / `C_ACCENT_DEEP` | `#14B8A6` / `#0D9488` | 主色 / 深主色 |
| `C_EMBER` | `#D97706` | 暖色锚点（不随主题变，见 6.2） |
| `C_SHADOW` / `C_PANEL_SHADOW` | `rgb(23,108,96)` | 卡片 / 面板投影（各自带 alpha） |
| `C_PANEL_TOP` / `C_PANEL_MID` / `C_PANEL_END` / `C_PANEL_LINE` | 由背景三段色派生 | 侧栏面板的竖直渐变与描边 |
| `C_BRAND_A` / `C_BRAND_B` / `C_BRAND_C` | `bg_top` / `accent` / `#D97706` | 品牌渐变字的三段 |
| `C_TIP_BG` / `C_TIP_BORDER` / `C_TIP_TEXT` | `card` / `line` / `text` | 即时提示气泡（常驻浮层，配色必须同源） |
| `BADGE` | 4 组（底, 字） | 分类徽章（恒定） |
| `_DELEGATE_SEL_BG` / `_DELEGATE_SEL_TEXT` / `_DELEGATE_SEL_LINE` / `_DELEGATE_HOVER_BG` / `_DELEGATE_TEXT` | `soft` / `deep` / `accent` / `bg` / `text` | 下拉弹出列表的行色（只能自绘） |

### 4.3 `C_FOCUS` 用 `deep` 而不是 `accent`

选中环叠在花了呼哨的图片上时，`#14B8A6` 明度偏高，容易被图片吃掉；
深一档的 `#0D9488` 才压得住。这是肉眼比对过的。

## 5. 布局

### 5.1 三栏

```
┌─ toolbar ────────────────────────────────────────────────────────────┐
│ [扫描源 ▸ 浏览…] [档位▾ 说明] [相似度 ──○──] [开始扫描] [主题▾]        │
├─ 左栏 190 ─┬─ 中栏（网格，拉伸）────┬─ 右栏 350 ─────────────────┤
│ 分组筛选    │  QListView            │  预览大图（PreviewPane）      │
│ （单选）    │  GroupDelegate 画卡片 │  ══ 可拖的 QSplitter ══      │
│ 保护规则×3  │                       │  标题 / 焦点 / 详情 / 理由     │
│ 缩略图大小  │                       │  [设为保留][标记删除][删除…]   │
│ 滑块 64–256 │                       │  [全部按推荐裁决][撤销所有裁决]│
├─────────────┴───────────────────────┴──────────────────────────────┤
│ StageProgress（多段进度） 状态 · 计数 [暂停] [导出报告…] [撤销上次删除] [执行删除…] │
└────────────────────────────────────────────────────────────────────┘
```

- **左栏是 `PanelSurface`**（自绘渐变 + 14px 圆角 + 投影），不是一块和背景
  糊在一起的空白。有了它才有「面板浮在画布上」的层次。
- **左栏不放品牌行。** 窗口标题栏本身写着「ImgDedup」，侧栏再重复一遍是纯噪音，
  还白占一行高度；`分组筛选` 直接顶到面板上沿，视觉上更干净。
  品牌露出由标题栏与应用图标承担。
- **筛选是单选**：「全部」或某一个分类，点一项就换一项，不需要按住 Ctrl。
- **三条保护规则是只读展示**（`setEnabled(False)`），界面上不提供关闭入口。
- **中栏只有网格**，不套 splitter：只有一格的时候再套一层是无意义的嵌套。
- **右栏是竖向 `QSplitter`**：上格预览 + 缩放控件（两者必须在同一格里，
  否则缩放控件会被 splitter 单独拖走），下格信息 + 按钮。
- 网格用 Qt 原生虚拟化：`_GroupListModel` 只做最薄适配，
  QListView 只对可见行调 `data()`，所以 10 万行和 10 行开销一样。

### 5.2 尺寸取值

| 项 | 值 | 理由 |
|---|---|---|
| 左栏 / 中栏 / 右栏初始宽 | `190 / 820 / 350` | 右栏要放预览大图，350 是"能看出细节"的下限 |
| 缩略图边长 | `64–256`，默认 `112` | 默认值对应一行约 4 张卡片，密度合适 |
| 预览解码边长 | `1024`（= `PreviewPane.STILL_SIDE`） | 滚轮最大放大到 16x，解 800px 放大后立刻糊成马赛克 |
| 预览最小尺寸 | `150` | 它住在 350px 宽的侧栏里，再大就会把侧栏顶宽 |
| 预览缓存 | 独立 `ThumbCache`，容量 12 | 不与网格共用：共用的话逛一圈预览就能把网格那 800 张小图挤光 |
| 预览缩放 | `0.2x ~ 16x`，每格 `×1.15` | 滚 5 格翻倍，手感刚好 |
| 右栏信息区最小高 | `300`（`setSizes([434, 300])`） | 选中态下信息区实测需要 264px，留 36px 给多选时折行的焦点标签 |
| 滚动一格 | `52px`（`WHEEL_STEP_PX`） | 约一行卡片的 1/4，见 9.3 |

### 5.3 具体设计点

1. **激活的筛选项带左侧竖条**：3px 圆角竖条、`accent`、紧贴左边缘。
   比"整行变色"更轻，也不会和复选框的勾选态打架。
2. **右栏按钮组主次分明**：
   - `[设为保留(N)]` → 实心 accent 底 + 白字（主操作，最安全）
   - `[标记删除(N)]` → 白底 + `line` 描边 + `DEL` 文字（次操作，有警示色）
   - `[立即删除…]` → 白底 + `DEL` 描边 + `DEL` 文字（危险操作，永不实心）
3. **缩略图尺寸滑块在左栏底部**：左边本来就是设置区，不跟工具栏的扫描参数
   抢注意力。改完必须 `doItemsLayout()` —— 卡片高度由尺寸派生，
   只改属性不重布局，新尺寸的缩略图会画到下一张卡片头上。
4. **即时提示气泡**（`InstantToolTip`）：悬停 / 聚焦当场弹出、**常驻不自动消失**，
   配色跟卡片同源，否则看起来像外挂的。
   必须由窗口持有强引用：只挂到控件上会被 GC，
   表现成"悬停没反应"（对象已销毁，事件过滤器还活着但控件没了）。

### 5.4 不建议做的

- **不要给列表加 drop-shadow**：上千个 item 逐个带阴影，滚动会掉帧。
- **不要给主按钮加自绘光晕**：hover 由 QSS 接管，而 QSS 给不了阴影；
  为它单加一个自绘按钮不值得。
- **不要做侧边栏折叠动画**：桌面工具追求"点了立刻到位"，150ms 动画纯属拖累。
  必须做的话上限 120ms、`OutCubic`。
- **不要让 accent 出现在大面积色块上**：整块工具栏染成薄荷会让图片颜色判断失真。
  accent 只出现在按钮 / 竖条 / 进度条 / 焦点环这些"小块"上。
- **不要给内容有上限的区域套滚动区**：`setWidgetResizable(True)` + `addStretch`
  + `WordWrap` 标签三者组合会让内层 widget 的最小高度 Qt 算不准，
  于是滚动条常驻、去不掉。信息区（5 行文字 + 5 个按钮）不需要滚动，
  用 `setMinimumHeight` + `setCollapsible(False)` 保证按钮永远露得出来即可。

## 6. 流萤专属点缀

流萤的灵魂是**"光点"**：角色本体是发光的萤火，主题的辨识度全在那圈光晕上。

### 6.1 两层光晕

```css
box-shadow: 0 0 10px 2px var(--accent),
            0 0 22px 6px var(--accent-soft);
```

Qt 侧用 `glow(color, strength)` 返回的 `QRadialGradient` 模拟：内层亮、外层散。
`strength` 夹在 0~1，用来控制"给多少光"。

### 6.2 用在哪

| 位置 | 强度 | 说明 |
|---|---|---|
| 进度条行进端 | 全强度 | 头部一个光点随进度移动，很出彩且不干扰阅读 |
| `BrandDot` | 全强度 | 带光晕的主色圆点。它不挂在主窗口上（见下），由需要品牌标识的场景单独使用 |

**暖色是角色锚点，不随主题变。** `C_EMBER`（`#D97706`）与背景渐变的暖米收尾
（`#FDF8EF`）都指向它：萤火虫的光是暖的，纯冷绿会显得像医疗软件。
五套主题里如果连它一起换掉，"流萤"就没了。

因此 `amber` 主题的品牌渐变做了特殊处理：它的 `accent` 本身就等于暖色，
所以渐变起点取主背景的**冷色端**（`bg_top`）、收尾再深一档到 `#D97706`，
才不至于塌成一片平色。

### 6.3 绝不用在哪

**缩略图边框、文字、列表行、卡片底。**
这些地方出现光晕会让图片边界发虚，而用户判断"这两张是不是同一张"时
最忌讳视觉干扰。

## 7. 自绘控件清单

QSS 表达不了的部分由这几个控件承担。判断"该不该自绘"的准则：
**QSS 给不了的（阴影、渐变、渐变文字、精确的命中测试）才自绘，其余一律交给 QSS。**

| 控件 | 为什么需要它 |
|---|---|
| `GradientPage` | 主背景的三段渐变（155°）。QSS 不支持渐变背景 |
| `PanelSurface` | 侧栏面板：竖直渐变 + 14px 圆角 + 描边 + 两层柔和投影。没有它侧栏是"一片没边界的空白" |
| `BrandText` | 渐变文字（等价 `background-clip: text`）：冷青 → 主色 → 暖琥珀 |
| `BrandDot` | 主色圆点 + 萤火光晕，`SIZE = 14` |
| `StageProgress` | 多段进度条：每个阶段一段。一根总进度条在"最后一公里"只能靠 99% 卡住来表达"还在算" |
| `glow()` | 径向渐变，模拟 CSS 的双层 `box-shadow` |
| `ComboItemDelegate` | 下拉弹出列表的行样式（QSS 上不了色，见 3.3） |
| `GroupDelegate` | 把一行画成一张分组卡片：标签行 + 缩略图条，含命中测试与选中 / 悬停态 |
| `PreviewPane` | 预览大图：等比装进可用区、滚轮以光标为锚点缩放、放大后可拖动平移、动图播放 |
| `InstantToolTip` | 即时弹出且常驻不消失的提示气泡 |

`BrandText` / `BrandDot` 不挂在主窗口上（侧栏不放品牌行）。
它们的消费者是 `tests/test_theme.py`（直接实例化做主题断言）
与 `dev/check_frozen.py`（把它们列为应存在于包里的符号）。

# 二、实现要点

## 8. 主题切换链路

### 8.1 `apply_theme()` 的四步，顺序不能换

```python
def apply_theme(app, key):
    t = theme(key)
    # 1) 就地刷新 widgets.py 的 QColor 常量
    # 2) 刷新自绘控件（GradientPage / PanelSurface / BrandText）
    # 3) app.setStyleSheet(build_qss(key))
    # 4) 给所有 QComboBox 装上自绘 delegate 并刷新它的行色
```

**必须先换常量、再换 QSS。** 常量是自绘控件重绘时现读的；先换 QSS 而没换常量，
就会出现「按钮变薄荷了、缩略图边框还是蓝的」这种半截状态。

### 8.2 常量必须**就地** `setRgb`，不能重新赋值

delegate / `BrandDot` / `StageProgress` 已经持有这些 `QColor` 的引用
（有些还是模块级默认参数）。把变量重新赋值成新对象，等于换了个人 ——
旧的那份永远不会变。所以一律 `color.setRgb(r, g, b)`。

用 `setRgb` 而不是 `setNamedColor`：后者在 PySide6 6.11 已废弃。

### 8.3 窗口是反查来的

`apply_theme(app, key)` 只拿得到 `app`，而 `GradientPage` / `PanelSurface` /
`BrandText` 都是**窗口的子控件**。更麻烦的是启动顺序：`apply_theme` 在
`MainWindow()` **之前**调用（为了让构造期读配色常量的控件一开始就拿到正确颜色），
那一刻窗口还不存在。

→ 双保险：`apply_theme` 里用 `topLevelWidgets()` 反查并刷新；
窗口构造完自己再调一次 `_sync_gradient()`。
`test_gradient_stops_follow_saved_theme_on_startup` 与
`test_switching_theme_updates_gradient` 各守一头。

### 8.4 `shadow` / `glow` 是 RGB 串，不是 hex

它们存的是 `"23, 108, 96"` 这种三元组字符串（自绘时拼 `rgba()` 用），
所以**不能走 hex 解析路径**：按 hex 解析会抛
`ValueError: invalid literal for int() with base 16: ', '`。
`apply_theme()` 里对它们有单独的解析分支，`test_shadow_rgb_refreshed` 钉着。

### 8.5 下拉弹出列表的选中行只能自绘

`QComboBox` 的弹出列表挂在 `QComboBox QAbstractItemView` 上，
但**只要 `QComboBox` 控件本身命中任意 QSS**，选中行就不再采纳
`::item:selected { background }`，也不采纳 view 的 `palette.Highlight`。
逐像素实测过的五种写法全部无效。

→ QSS 里那几条只管几何（行高 / 内边距 / 圆角），行色交给
`widgets.ComboItemDelegate` 画；`apply_theme` 第 4 步负责给它换色。

顺带一条：**QSS 选择器不要写裸 `QListView`**。`QComboBox` 的弹出列表 view
是 `QListView` 的子类，裸选择器会把"背景透明 + 无边框"也套上去，
于是弹出的那块底是透明的，看起来像"列表里有个空白选项"。
要限定成 `QListWidget`。

## 9. 滚动手感

### 9.1 现象与根因

在 `ScrollPerPixel` 模式下，Qt 把 `scrollBar.singleStep` 设成**一个 item 的高度**
—— 而这里的 item 是**一整行卡片**：

```
缩略图 112px 时 singleStep = 1018px
滚轮位移 = singleStep × wheelScrollLines(默认 3) = 3054px
而整个可滚动范围只有 266px
→ 一格滚轮 = 3 次见底，中间全跳过
```

这是算术必然，与分组数量无关；分组少时反而更明显（可滚范围更小）。
所以 `window.eventFilter` 拦截 `QEvent.Type.Wheel`，按固定像素滚动。

### 9.2 三个易错点

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 触控板事件 `angleDelta() == 0` | 提前 `return` 会把触控板整个吃掉 | `delta = y() or x()` 与 `pixelDelta` 并列判空，两者都 0 才返回 |
| 触控板猛滑（pix = -300） | 原样透传 → 一冲 300px | 限幅到 ±`WHEEL_STEP_PX` |
| 慢速微拨（delta = -30） | `int(-30/120) == 0` → 滚不动 | 任何非零增量至少走一格 |

### 9.3 实测

| 场景 | 位移 |
|---|---|
| 鼠标一格 | `52px`（Qt 默认行为下是 266px，即整屏） |
| 触控板 `pixelDelta = -9` | `9px` |
| 触控板 `pixelDelta = -300` | `52px`（限幅） |
| 微拨 `delta = -30` | `52px`（不截断） |
| 横向滚轮 | 当垂直用，`52px` |

实测卡片高 190px、可滚范围 768px，**需 16 格到底**。

`tests/test_wheel.py` 钉住这五条，并验证过能抓回归：
把 `WHEEL_STEP_PX` 改成 400 → 立刻有两条失败。

# 三、操作手册

## 10. 改配色

1. 改 `imgdedup_ui/theme.py` 的 `THEMES`。一套主题要同时给全
   `name / accent / deep / soft / line / bg / card / text / muted / hover /
   grad_a / grad_b / glow / bg_top / bg_mid / bg_end / shadow`。
   注意 `glow` 与 `shadow` 是 `"R, G, B"` 字符串（见 8.4）。
2. 如果新增了自绘控件要用的字段，在 `apply_theme()` 里加一条**就地 `setRgb`**
   （见 8.2），不要重新赋值。
3. 跑 `tests/test_theme.py`：token 完整性、语义色跨主题恒定、
   QSS 与 widgets 常量同步、渐变页 / 面板 / 品牌字跟随主题、光晕强度夹取。
4. `dev/shot_themes.py` 离屏截五套主题各一张，人眼看结构。
   离屏没有 CJK 字体，中文是方块，**只看位置与层级**。

## 11. 两条不能破的规则

- **裁决三态与分类徽章色不随主题变。** 用户对"绿 = 安全、红 = 危险"的直觉
  不能为了好看让路。
- **暖色锚点不随主题变**（`C_EMBER` / `BRAND_EMBER` / 背景暖米收尾）。
  它是"萤火虫的暖光"，换掉它"流萤"就没了。

## 12. 新增自绘控件时

先问一句：**QSS 能不能表达？** 能就别自绘。

确定要自绘之后：

1. 配色常量放 `widgets.py`，并在 `apply_theme()` 里加一条就地 `setRgb`；
2. 如果它挂在窗口上，把刷新挂进 `window._sync_gradient()`（`apply_theme`
   从 `app` 反查不到新建之前的控件，见 8.3）；
3. 记住 QSS 的三条限制（3.3）与 `QComboBox` 弹窗那条（8.5）；
4. 在 `tests/test_theme.py` 里加一条"切主题后它跟着变"的断言 ——
   自绘控件最容易出现的就是"半截状态"：主界面变了、它没变。
